# OvO 学术成果分享平台软件需求规格说明书

版本 V0.3　日期 2026-10-12　状态 提交评审稿

编写单位：OvO小组；编写方式：AI辅助起草与校核；成员复核与共同冻结：待团队签认。本文件及其引用分册共同构成SRS，分册不是可省略附件。目标读者为课程评审者、组内需求负责人及后续开发测试人员。

## 1 引言

### 1.1 文档目的

把V1.9需求转化为可观察、可验证、可追踪的行为约定。本版覆盖107条功能与创新子需求、17条非功能子需求，给出每条输入输出、条件、分支、权限、状态和验收场景。验收场景描述未来实现应满足的结果，不代表系统已经通过测试。

### 1.2 系统范围

聚合论文、专利、科研项目、获奖四类成果元数据，提供公开检索、详情、学者门户、门户认领、维护、采集治理、更新、统计、管理和合作关系探索。四类均须可查，最终清洗去重总量至少1万条。平台不承担投稿出版、全文托管、付费下载、成果交易、私信或学术质量认证。

## 2 系统总体说明

### 2.1 产品定位与边界

服务普通检索者、科研人员和平台治理人员。通过来源聚合与身份治理形成可追溯成果视图；来源记录、成果实体、学者档案、用户账号及门户授权各有独立身份与生命周期。

### 2.2 用户角色

| 角色 | 业务目标与边界 |
|---|---|
| 访客 | 浏览公开成果、学者、统计和合作关系，无需登录 |
| 登录用户 | 管理本人账号，提交和跟踪本人认领申请 |
| 门户管理者 | 已获指定门户授权的登录用户，只管理该门户及其关系 |
| 管理员 | 按具体能力审核、治理、维护来源账号分类或查询审计 |
| 外部数据来源 | 提供公开或获准元数据，不具有人类账号权限 |

系统自动处理是内部责任主体，不作为系统总体用例图的外部参与者。测试与维护人员是验证角色，不自动获得生产管理员权限。

### 2.3 运行场景与外部依赖

公开读取依赖平台已收录数据，不应强依赖来源即时在线。采集依赖已登记的公开API、获准文件或网页；来源失败须保留历史。审核依赖管理员和受控证明；统计依赖已生效公开关系及声明口径。

### 2.4 约束与假设

当前只规定需求和模型，不固定架构、数据库或接口实现。至少两种独立来源输入需在后续采集验收核对；模拟记录必须标识。性能2秒、一致性60秒沿用V1.9待评审目标。未冻结事项集中登记，不被默认为已批准。

## 5 创新与可选需求

IN01在基础论文合作网络上增加领域、机构筛选及两学者最短路径，逐跳给出论文证据。领域和机构筛选不要求先选两个端点。O01相似论文推荐、O02轻量个性化推荐不在本版验收范围；若未来实施，须另建子需求及同意、偏好查看清除规则，不能阻断Must和IN01。

## 6 业务流程与状态模型

认领流程为提交、校验、待审核、补充循环、通过或驳回。冲突未解决禁止通过；通过与授予目标门户权限构成同一业务成功结果。

| 图 | 视图与依据 |
|---|---|
| DGM-ACTIVITY-01 待绘制 | FR05、UC-05、UC-06，含补充、驳回、冲突和并发重验 |
| DGM-STATE-01 待绘制 | FR08、FR10、UC-09，六种状态与停止重试 |
| DGM-STATE-02 待绘制 | FR05，待审核、待补充、已通过、已驳回 |

完整状态、触发与禁止迁移见 [状态登记表](cross-cutting-matrices.md)。门户认领摘要由授权和申请派生，不能与申请状态合成一个状态机。[图模目录](../uml/README.md)只登记后续制作要求，当前文档不声明四图或图文校验已完成。

## 7 数据需求与业务规则

[数据与规则](data-and-rules.md)定义对象、必填和未知语义、四类专属字段、日期与标识、公开策略、审核字段范围、计数、合作和热点口径。统一规则为 [BR-01至BR-20](business-rules.md)，适用矩阵见 [横切矩阵](cross-cutting-matrices.md)。本组细化建议的决策归属和冻结状态均单独说明。

## 8 权限与安全需求

以 [权限矩阵](cross-cutting-matrices.md)为统一定义。角色能力和具体门户授权同时满足才允许受保护操作；页面是否有按钮不构成授权。证明仅申请人本人及对应审核管理员可读，已有门户管理者不能读取竞争申请人的证明。公开页面、错误反馈和审计均不泄露凭据或证明原文。

## 9 非功能需求

[非功能逐条规格](modules/detailed/nonfunctional-detailed.md)覆盖NF01至NF08共17条：可用性、性能、安全、恢复、一致性、隐私、维护、工程测试。性能测试规定样本、环境、持续时间和P95口径；恢复和覆盖率保留明确失败判据。当前提供测试计划与验收条件，实际系统验证属于后续实现阶段。
