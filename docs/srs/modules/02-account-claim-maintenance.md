# 功能域二：账号、门户认领与成果维护（FR04～FR07）

> 状态：V0.1 Draft｜父基线：V1.9｜关联用例：UC-04～UC-08

## FR04 账号登录与权限校验

### 子需求

| 编号 | 可观察能力 |
| --- | --- |
| FR04-S01 | 用户可注册账号；重复标识、无效输入和不完整信息得到明确反馈。 |
| FR04-S02 | 有效账号可登录并退出；失败登录不暴露账号是否存在等不必要信息。 |
| FR04-S03 | 每次受保护操作均校验登录状态、账号状态、角色和对象级授权。 |
| FR04-S04 | 被停用或失效的账号不能继续受保护操作，已有公开档案不因此删除。 |
| FR04-S05 | 越权操作被拒绝并产生可审计的安全事件摘要。 |

### 参与者与流程

- **参与者：** 访客、登录用户、门户管理者、管理员。
- **前置条件：** 注册时账号标识可用；登录时账号已注册且未停用。
- **主流程：** 用户提交凭据→系统校验→建立登录状态→用户发起受保护操作→系统校验角色及目标对象授权→允许操作→退出后登录状态失效。
- **异常流程：** 凭据错误、账号停用、登录过期或对象未授权时拒绝操作并给出不泄密的反馈；直接绕过页面调用同样被拒绝。
- **权限/规则：** BR-02、BR-03、BR-18；前端隐藏按钮不能替代服务端权限判定。

### 验收条件

- **AC-FR04-S01-01：** Given 标识已注册，When 再次注册，Then 拒绝创建重复账号并提示标识不可用。
- **AC-FR04-S03-01：** Given 普通登录用户未获门户甲授权，When 直接提交门户甲修改，Then 操作被拒绝且公开数据不变。
- **AC-FR04-S04-01：** Given 账号被停用，When 使用既有登录状态访问受保护操作，Then 被拒绝，但其关联的公开学者档案仍可浏览。

## FR05 门户认领申请与审核

### 子需求

| 编号 | 可观察能力 |
| --- | --- |
| FR05-S01 | 登录用户可选择未认领或需要核验的学者档案并提交认领信息及必要证明。 |
| FR05-S02 | 提交前校验完整性、本人声明和目标档案状态；不合格申请不进入审核。 |
| FR05-S03 | 管理员可查看申请、证据摘要和冲突提示，并作补充、通过或驳回决定。 |
| FR05-S04 | 待补充申请可由申请人补充后重新进入待审核；历史材料和决定保留。 |
| FR05-S05 | 通过后授予目标门户对象级管理权限；驳回后不授予权限并显示原因。 |
| FR05-S06 | 已有管理人的冲突认领保持原授权不变，进入人工争议处理。 |
| FR05-S07 | 申请人可查看本人申请状态、要求补充内容和最终结果。 |

### 参与者与条件

- **主要参与者：** 登录用户、管理员；**前置条件：** 用户已登录，目标档案存在。
- **触发条件：** 用户提交有效认领申请。
- **成功后置：** 申请通过后新增对象级授权并记录审核；其他结果不改变授权。

### 主成功流程

1. 用户选择目标档案，填写认领信息、本人声明并提交规定证明。
2. 系统校验完整性、文件约束、重复申请和目标档案冲突，创建“待审核”申请。
3. 管理员查看申请、公开身份线索和受控证明材料。
4. 管理员批准申请并填写决定依据。
5. 系统将申请置为“已通过”，授予目标门户管理权限，记录审计并通知申请人。

### 备选与异常流程

- **A1 待补充：** 管理员说明缺失项→申请进入待补充→用户补充并重新提交→回到待审核。
- **A2 驳回：** 管理员填写可理解的原因→申请进入已驳回→不授予权限。
- **E1 冲突认领：** 目标已有管理人或存在并发申请时，不覆盖原授权，标记冲突并转人工处理。
- **E2 重复提交：** 同一用户对同一档案已有进行中申请时拒绝重复创建并引导查看原申请。
- **E3 并发审核：** 已被其他管理员处理的申请不可再次产生不同最终决定。

### 权限与业务规则

- 证明材料仅申请人和有审核权限的管理员可访问，执行 BR-01、BR-03、BR-04、BR-18、BR-19。
- 认领通过只授予门户管理权，不自动确认任何成果归属或学术真实性。
- 撤回、授权转移等未在 V1.9 冻结的扩展不纳入本版承诺。

### 验收条件

- **AC-FR05-S02-01：** Given 申请缺少必需声明，When 用户提交，Then 不创建待审核申请并指出缺失项。
- **AC-FR05-S04-01：** Given 管理员要求补充，When 用户补充并重新提交，Then 状态由待补充回到待审核且历史要求可追溯。
- **AC-FR05-S05-01：** Given 申请审核通过，When 用户再次访问目标门户管理操作，Then 获得该门户权限但不能管理其他门户。
- **AC-FR05-S06-01：** Given 门户已有管理人，When 新申请被提交，Then 原授权保持不变且申请进入人工冲突处理。

## FR06 学者门户信息维护

### 子需求

| 编号 | 可观察能力 |
| --- | --- |
| FR06-S01 | 门户管理者可维护允许修改的简介、公开领域和展示设置。 |
| FR06-S02 | 系统区分可直接生效与须审核的修改；重要公开信息待审期间保留旧版本。 |
| FR06-S03 | 管理者可查看提交状态、审核结果和已生效版本。 |
| FR06-S04 | 所有重要修改保留前后值、操作者、时间、原因和审核结果。 |
| FR06-S05 | 未授权者和被停用账号的修改请求被拒绝。 |

### 参与者与流程

- **参与者：** 门户管理者、管理员；**前置条件：** 对目标门户具有有效授权。
- **主流程：** 打开管理页→系统返回允许编辑字段及公开版本→用户修改并提交→系统校验→按规则直接生效或进入待审核→结果通知并留痕。
- **异常流程：** 字段超长、包含不可公开信息、授权失效或并发版本冲突时拒绝提交，公开版本不变。
- **权限/规则：** BR-03、BR-05、BR-18；私人联系方式和审核材料不进入公开简介。

### 验收条件

- **AC-FR06-S01-01：** Given 用户只获门户甲授权，When 修改门户甲简介，Then 可提交；修改门户乙时被拒绝。
- **AC-FR06-S02-01：** Given 重要公开字段需审核，When 提交修改尚未通过，Then 访客仍看到旧值，管理者能看到待审状态。
- **AC-FR06-S04-01：** Given 修改通过，When 管理员查询记录，Then 可查看前后值、提交人、审核人和时间。

## FR07 学者成果确认、补录与纠错

### 子需求

| 编号 | 可观察能力 |
| --- | --- |
| FR07-S01 | 门户管理者可逐项或批量确认系统为本人生成的候选成果关系。 |
| FR07-S02 | 可补录已存在且可核验的成果元数据及来源，不提供投稿或发表。 |
| FR07-S03 | 可对遗漏、误归属、字段错误或解除本人关联提交纠错申请和依据。 |
| FR07-S04 | 管理员可比较当前公开值、申请值和来源证据，批准或驳回变更。 |
| FR07-S05 | 通过后更新公开关系/字段并传播到门户、检索和统计；待审时不公开。 |
| FR07-S06 | 解除个人关系不删除成果实体、来源记录或其他参与者关系。 |
| FR07-S07 | 申请人可查询每项变更的状态、结果和驳回原因。 |

### 参与者与条件

- **参与者：** 门户管理者、管理员；**前置条件：** 用户对目标门户具有有效授权，目标成果或补录来源可识别。
- **触发条件：** 用户提交确认、补录或纠错。
- **成功后置：** 审核通过的变更形成新的公开业务结果并保留证据与审计记录。

### 主成功流程

1. 门户管理者选择候选成果或填写补录/纠错内容，说明操作类型和依据。
2. 系统校验对象级授权、必填字段、来源和是否存在重复进行中申请。
3. 无需人工处理的明确本人确认按规则记录；影响共享成果字段、争议归属或解除关系的请求进入待审核。
4. 管理员比较公开版本、申请内容和来源证据，批准或驳回。
5. 系统在批准后更新对应关系或公开字段，保留原来源事实，并向申请人反馈结果。

### 备选与异常流程

- **A1 批量确认：** 仅对无冲突候选批量生效；有冲突项逐项进入核验，不因批量操作跳过规则。
- **A2 补录疑似重复：** 不直接创建第二个成果，提示候选并进入去重核验。
- **E1 越权：** 操作涉及其他门户或其他学者关系时拒绝。
- **E2 解除关联：** 只改变本人关系；若是唯一关系，成果仍按其公开和来源状态保留。
- **E3 审核期间源数据变化：** 标记证据已变化并要求管理员重新确认，不静默覆盖。

### 权限与业务规则

- 执行 BR-03、BR-05～BR-10、BR-18、BR-19。
- 本人确认只确认该学者与该成果的关系，不替其他作者确认，也不构成质量认证。
- 补录必须指向已有且可核验的成果，不接受原创内容投稿。

### 验收条件

- **AC-FR07-S01-01：** Given 候选成果无冲突，When 门户管理者确认，Then 关系标记为本人确认且其他作者关系不变。
- **AC-FR07-S02-01：** Given 补录记录与现有 DOI 相同，When 提交，Then 不创建重复成果并提示进入现有成果关联/核验流程。
- **AC-FR07-S05-01：** Given 纠错尚待审核，When 访客查看详情，Then 仍显示原公开值；审核通过后相关门户、检索和统计采用新结果。
- **AC-FR07-S06-01：** Given 多名学者关联同一成果，When 一人解除本人关联，Then 成果及其他学者关系继续存在。
