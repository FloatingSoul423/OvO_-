# 详细规格二：账号、认领与维护

> 状态：V0.2 Draft｜生成依据：V1.9、模块概览和公共规则｜所有条目须经人工评审后冻结

## 公共说明

本分册逐条采用统一 SRS 模板。为避免重复，术语、参与者定义、BR-01～BR-20 和 UC 注册表以 `../../OvO-SRS-Draft.md` 为公共真源；每条仍显式给出适用角色、条件、流程、数据、状态、权限、规则、验收与关联项。实现技术不属于本分册。

本分册共包含 **24** 条子需求。

## FR04-S01 用户可注册账号；重复标识、无效输入和不完整信息得到明确反馈

- **父需求/优先级：** FR04 / Must
- **主要/相关参与者：** 访客、登录用户 / 管理员

### 规格字段

| 字段 | 规格 |
|---|---|
| 需求描述 | 系统应满足以下要求：用户可注册账号；重复标识、无效输入和不完整信息得到明确反馈；遵守本分册公共上下文和 BR-02、BR-03、BR-18，不得通过未声明的实现假设改变需求语义。 |
| 前置条件 | 账号输入满足最小要求；受保护操作具有可验证登录状态；适用规则、公开范围和当前版本可识别。 |
| 触发条件 | 用户注册、登录、退出或发起受保护操作，且本条能力被调用。 |
| 输入/业务数据 | 账号标识、凭据、账号状态、角色、目标对象和操作类型；当前对象版本、数据公开范围和适用规则版本。 |
| 输出/可观察结果 | 账号操作结果、登录状态或明确的拒绝原因；失败、无结果、待处理或权限不足须与成功明确区分。 |
| 状态变化 | 账号可由未注册变为有效；登录状态建立/失效；停用不删除档案；无状态变化时保持原状态，不创建伪状态。 |
| 权限规则 | 每次受保护操作同时校验角色和对象级授权；界面隐藏不替代角色和对象级鉴权。 |
| 业务规则 | BR-02、BR-03、BR-18；冲突时进入评审，不在本条私自重定义。 |
| 备选流程 | A1：输入可修正时指出具体字段并保留其他合法内容。 A2：操作无需改变业务状态时只返回结果，不创建虚假状态。 |
| 异常流程 | E1：输入无效、对象不存在或状态不允许时拒绝操作，指出可修正原因。 E2：依赖失败或处理超时时返回失败/未完成状态，不伪装成无结果或成功。 E3：并发版本已变化时不覆盖新结果，要求刷新后重新判断。 E4：权限不足时拒绝操作，业务数据保持不变，并记录必要的安全或审计摘要。 |

### 主成功流程

1. 参与者发起“用户可注册账号；重复标识、无效输入和不完整信息得到明确反馈”。
2. 系统校验身份、权限、输入完整性和当前状态。
3. 系统执行“用户可注册账号；重复标识、无效输入和不完整信息得到明确反馈”并产生明确结果。
4. 系统保存必要状态与审计信息并向参与者反馈。

### 验收条件

- AC-FR04-S01-02：Given 账号输入满足最小要求，When 访客执行本条操作，Then 可观察结果必须满足“用户可注册账号；重复标识、无效输入和不完整信息得到明确反馈”，并返回“账号操作结果、登录状态或明确的拒绝原因”中与本条相关的结果；不满足该行为即判定失败。

### 关联项

- **用例：** UC-04；**非功能需求：** NF01、NF03、NF06；**数据对象：** UserAccount、Authorization、AuditLog；**关联图：** DGM-USECASE-01（图模任务完成后核对）。
