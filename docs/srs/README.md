## 当前目标

本组 V0.4 有 124 条逐条业务场景、163 个独立 AC、15 个完整用例及权限状态规则。已移除重复的通用验收模板，关键场景配置边界验收。当前为提交评审稿，需团队签认；两张状态图已有图源，另两张必需图待归档与一致性核查。结构检查不能代替业务评审。

## 建议结构

1. 引言；
2. 系统总体说明；
3. 用例模型；
4. 功能需求规格；
5. 创新与可选需求；
6. 业务流程与状态模型；
7. 数据需求与业务规则；
8. 权限与安全需求；
9. 非功能需求；
10. 验收与追踪。

## 模块划分

- FR01～FR03：检索、详情与学者门户；
- FR04～FR07：账号、认领、门户与成果维护；
- FR08～FR10、FR15～FR16：采集、治理、更新、消歧和来源追踪；
- FR11～FR14、IN01：统计、合作网络、热点、管理和创新；
- NF01～NF08：非功能与横切规则。

成员模块文档放入 `modules/`。模块文件创建后应注明状态、负责人、复核人、父需求和待决事项；未经联合评审不得宣布总 SRS 已冻结。

## 单条子需求最小字段

- 父需求、优先级、主要/相关参与者；
- 需求描述、前置条件和触发条件；
- 主成功流程、备选流程和异常流程；
- 输入、可观察输出和状态变化；
- 权限规则和业务规则；
- Given-When-Then 验收条件；
- 关联用例、NF、数据对象和图。

SRS 不写数据库表、API URL、框架、缓存、消息主题或微服务数量。
