# 需求分析阶段 AI 使用声明

> 团队：03组 可御风雪可燃冰　作业：作业 3 需求分析　版本：V1.0　日期：2026年10月24日

## 1 声明结论

本团队在业务对象梳理、模型草拟、文档组织、一致性检查和图形渲染中使用了生成式 AI。AI 只提供候选结构、文字和检查建议，需求边界、业务规则、UML 关系、最终取舍和提交责任由团队成员承担。未经过人工理解、核对和签认的输出不作为最终成果。

## 2 双组工具与路线

|小组|主要 AI 与工具|主要用途|人工验证|
|---|---|---|---|
|CognitaNexus|DeepSeek、Pi、PlantUML、Git|规则细化、算法边界、文档结构维护和跨文件检查|按 FR/AC/BR/SPEC 核对；负责人确认实际模型版本和提示记录|
|OvO|ChatGPT、Codex、PlantUML、CodeArts Modeling、Git|用户场景、异常闭环、UML 草拟、文档生成、追踪与静态检查|按 SRS、用例、状态、权限和课程清单核对；平台实际导入后签认|

两组采用不同建模侧重点：CognitaNexus 更强调规则细粒度、证据和算法边界；OvO 更强调角色、主流程、异常流程和可观察状态。联合评审不按篇幅或模型原文二选一，而以课程要求和共同需求语义为准形成统一版本。

## 3 本阶段生成内容及复核

|环节|AI 辅助内容|人工检查要点|当前证据|
|---|---|---|---|
|业务对象识别|从 SRS 名词、状态和审计对象生成候选清单|合并同义词；分离账号/学者、申请/授权、成果/来源|对象清单、类图和一致性矩阵|

|认领审核时序图|整理认证、受理、补充、冲突、通过和驳回分支|申请状态与授权分离；冲突不覆盖既有授权|图源和预览|
|检索处理时序图|整理校验、过滤、排序、分页、空结果和错误|公开范围、稳定分页、空结果与故障可区分|图源和预览|
|Word 文档|生成结构、表格、图注和版本材料|成员逐段理解；核对编号、范围、图片清晰度和待填项|DOCX 渲染检查记录|

## 4 人工验证规则

1. 每张图由主责成员逐条讲解参与者、消息、分支和业务结果；不能讲清的内容删除或重写。
2. 图中每个关键对象和状态均能回溯到 SRS 或需求建模成果；无依据的技术实现不进入分析模型。
3. PlantUML 通过语法渲染只证明图源可生成，不证明业务正确；CodeArts ZIP 通过结构校验也不等于平台已成功导入。
4. CodeArts 源文件必须由成员在平台实际打开、精修、重新导出，并与 Word/PPT 中图片一致。
5. 任何性能、容量、采集量或人工调研结果，只有存在实际证据时才写为已完成；计划值和验收目标不得写成实测结果。
