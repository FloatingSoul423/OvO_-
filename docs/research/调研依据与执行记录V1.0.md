## 5. 数据源与合规核查台账

|来源|范围、标识与访问条件|当前准入判断|未完成的实证核查|
|---|---|---|---|
|OpenAlex|Works、Authors、Institutions 等实体；官方说明元数据 CC0；API 有预算、频率与分页限制，规模使用建议申请密钥|论文与作者关系候选；只取课程所需元数据，记录 OpenAlex ID、DOI、更新时间和来源条件|抽样字段完整率、学科覆盖、重复率、真实请求预算|
|Crossref|公开 REST API 无需注册可访问；建议 polite 身份；不同访问层速率不同|DOI 核验与论文元数据候选；元数据开放不等于摘要/全文皆可任意复制|字段级可用性、摘要版权、请求限制与失败响应|
|dblp|计算机领域书目元数据按 CC0 提供；可下载 XML 数据集|计算机领域补充来源；不能代表所有学科|作者消歧、更新频率、字段与 OpenAlex 重叠率|
|专利官方公开来源|拟以主管机构的公开检索/开放数据为候选，需按法域及申请号区分|暂未批准采集|来源条款、机器访问、字段、状态更新时间|
|项目与获奖公告|拟以资助机构、学校或主管部门的公开公告为候选|暂未批准采集|记录 ID、许可、发布日期与更正机制|

准入检查清单：①合法来源和允许用途；②获取方式及频率；③允许展示的字段和附件；④标识的作用域；⑤来源时间、采集时间与更新时间；⑥撤回、更正和失效处理；⑦是否包含隐私或版权内容；⑧数据性质“真实/模拟/混合”。未填写并核验上述项目的来源，不应在正式任务中启用。公开页面可见不等于获得批量抓取或全文再发布许可；演示时仅用合法元数据与显式模拟数据。

## 6. 待执行的一手访谈提纲

访谈前说明课程用途、预计时长、匿名处理和可随时退出；不要求提供身份证、密码、未公开研究内容或受版权保护的全文。记录仅需角色类别、日期、方式、问题回答摘要与经过同意的引述编号。下列问题为计划，不是已发放问卷。

### 6.1 普通访客

1. 最近一次查找某位学者或某项成果时，从哪里开始？在哪一步不能确定结果可信？
2. 类型、年份、机构、领域、数据来源和更新时间中，哪些筛选最常用？为什么？
3. 遇到“查不到”“条件填错”“系统暂时失败”时，分别希望看到什么下一步？

### 6.2 科研人员

1. 你现在如何维护个人成果列表？哪些信息重复填写最费时？
2. 如果平台自动列出疑似属于你的成果，你愿意怎样确认、排除或提出更正？
3. 门户认领应提供哪些最少证据才可接受？哪些材料你不愿上传？
4. 同名作者、旧机构或预印本/正式版混淆时，你期望怎样看到处理过程？

### 6.3 平台管理员

1. 新增数据来源时，必须核对哪些许可、字段、标识与更新条件？
2. 哪些清洗或身份候选可以自动处理，哪些必须人工复核？
3. 采集失败、来源撤回、误合并拆分和争议认领分别需要保留什么审计证据？
4. 当统计口径或分类不一致时，你如何定位并解释差异？

若执行，建议每类覆盖不同经验者，先做一次预测试；不预设访谈人数为已完成。访谈后将“观察事实—需求解释—FR/BR 映射—反例/分歧—复核决定”逐行入账。
