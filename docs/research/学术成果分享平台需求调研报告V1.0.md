# 学术成果分享平台需求调研报告

OvO 小组｜V1.0｜2026 年 10 月 12 日｜组号与成员分工待团队填写

## 摘要

本报告为课程“学术成果分享平台”需求建模提供证据依据。已完成公开研究统计结果汇编、原始论文复核、公开数据源文档级核查，以及与本组 SRS 的需求映射；本组尚未实施访谈、问卷、可用性测试或批量采集试验。因此，文中“三类用户诉求”是基于二手证据和场景推导的待验证需求假设，不是受访者原话；各研究的样本、年代和平台不同，不合并计算总体比例。具体来源、执行台账和待执行提纲见[调研依据与执行记录](调研依据与执行记录V1.0.md)。

## 1. 调研目标、范围与判定口径

调研回答四个问题：谁需要平台、现有服务有什么缺口、哪些公开数据可依法用于课程原型、哪些需求应优先落实。目标用户分为普通访客、科研人员、平台管理员；成果范围限定论文、专利、科研项目、获奖四类。需求优先级沿用本组 SRS：核心检索、展示、治理、认领与统计为 Must；创新项和扩展项单列，不把设计建议冒充 V1.9 已确认要求。

本报告区分“事实证据”“需求推论”“待验证事项”。事实证据须能指向文献、平台公开说明或本组已有文档；需求推论须映射到 FR/BR；缺少本组用户反馈或数据样本时，标记待验证。验收条件以 SRS 为准，不把外部调查百分比直接转成系统性能指标。

## 3. 现成统计结果的证据摘要

|来源与样本|可引用的结果|对本项目的启发|外推限制|
|---|---|---|---|
|Nature 2014 年科研社交调查，超过 3500 名、95 个国家或地区的受访者|超过 88% 知晓 ResearchGate；经常访问者不足半数|“知道平台”不等于持续使用；检索、维护收益必须明确|年份较早、跨国自选样本，不代表本校|
|Meier 与 Tunger，PLOS ONE 2018 年，695 名研究人员|原统计报告摘录显示多数受访者每周用于平台及资料维护的时间不足一小时，且部分平台评分机制不易理解|降低维护负担；解释统计口径，不使用不可解释的单一分数|研究对象和平台不同；以原文口径为准，不合并其他研究|
|《数字图书馆论坛》2024 年研究，12 次访谈、221 份问卷、183 份有效问卷|Kano 分析中“文献获取”的 Better 系数为 0.748，“科研协同”为 0.661|先满足查找、获取线索与可信成果展示，再考虑社交扩展|该调查的人群与场景未必等同本平台|

上述数字保留原研究各自的分母与定义，不相加为“总样本量”，不求平均，不推断本组用户比例。PLOS ONE 的 83% 指每周搜索、浏览等活动不足一小时，94% 指每周维护个人资料不足一小时；二者不能统称“平台使用不足一小时”。这些结果支持“可检索、低维护、可解释、可追溯”的设计方向；具体优先级仍由课程任务书和 V1.9 需求基线决定。

## 4. 同类平台与数据源调研记录

|对象|本阶段核查到的定位|对本系统的借鉴或差异|仍需核实|
|---|---|---|---|
|ResearchGate|科研人员资料与成果展示平台；已有公开用户研究|借鉴作者主页与成果聚合；不照搬平台评分或社交机制|实际操作流程、当前功能变化、使用条款|
|OpenAlex|官方文档列出 works、authors、institutions 等实体与 API|可作论文、作者、机构关系的候选来源；保留原始来源 ID|课程使用的配额、覆盖率、字段缺失率及更新方式|
|Crossref|公开元数据 REST API；DOI 等持久标识可用于论文核对|用 DOI 辅助同一论文判断，不能把元数据许可误当全文授权|字段级许可、摘要/全文权利、请求限制|
|dblp|计算机领域文献目录，官方声明元数据许可|可辅助计算机领域成果与作者核验|跨学科覆盖不足；接口与再分发条件|
|专利、项目、获奖公告|拟优先核查主管部门或机构的公开来源|四类成果需分别定义标识与日期语义|具体来源、授权方式、稳定 ID、更新频率均未验证|

候选数据源准入须逐项登记：来源主体和链接、可用范围、许可证/使用条件、获取方式、标识作用域、更新时间、字段覆盖、删除更正渠道。仅“网页可见”不等于允许抓取或再发布；不复制受版权约束的论文全文、付费内容或不必要的个人信息。课程模拟数据必须显式标记，不与真实数据混淆。来源失效时保留已有合法历史记录的出处和最后核查时间，是否继续公开依来源条件复核。

## 5. 三类用户诉求与场景

|用户|典型任务与阶段性诉求|对应需求|需要一手验证的问题|
|---|---|---|---|
|普通访客|按关键词与类型查找成果或学者；组合筛选、稳定翻页；看到可信来源、更新时间和“无结果/失败”的不同提示|FR01、FR02、FR16；BR07、BR14|常用检索词、筛选顺序、是否理解真实/模拟标识|
|科研人员|少量操作维护个人门户；申请认领身份；核对成果归属并提出更正，不因同名被自动合并|FR03—FR07、FR15；BR09、BR10|认领材料可接受程度、归属纠错流程、隐私顾虑|
|平台管理员|登记合法来源、运行与追踪采集任务；处理清洗/去重/身份候选；复核统计并审计人工决定|FR08—FR14、FR16；BR07—BR18|人工核验工作量、异常分类、可接受的批处理规模|

这些诉求是基于桌面调研和课程场景形成的“待验证用户故事”，并非来自本组受访者。管理员对来源许可和纠错负责；科研人员对本人申诉、认领和更正负责；访客仅访问可公开的信息，三者权限不混用。

## 6. 需求边界与优先级

|级别|本阶段纳入|边界说明|
|---|---|---|
|P0 / Must|四类成果收录与来源登记；公开检索/详情；门户和认领；采集、清洗、去重、更新、身份消歧；可解释统计与权限审计|追踪本组 SRS 的 FR01—FR16 与对应 NF；必须保留异常路径|
|P1 / Should|减少手工维护的批量核验辅助、候选解释、检索体验优化|只能在不破坏 P0 准确性与审计性的前提下安排|
|P2 / Could|创新分析、合作网络与额外互动功能|按 IN01 和课程资源评估；不得替代基础质量|
|明确不在本阶段承诺|论文全文托管、付费资源绕过、自动认定同名作者、自动合并仅标题相似成果、未获授权的大规模爬取|超出课程目标或证据/许可不足，需另行评估|

“去重后不少于一万条”是课程数据规模目标，不等于一万条来源记录；同一实体的多来源记录只计一次。统计需说明真实、模拟、混合数据口径；不同分类求和可能超过全局唯一实体数。

## 7. 阶段性结论、风险与下一步

现有证据支持以“可信成果索引＋可维护门户＋人工可控的数据治理”为核心：检索优先于复杂社交，稳定标识优先于标题相似，人工确认优先于有争议的自动合并，统计展示必须同时给出处和口径。当前最大风险不是缺少功能设想，而是缺少本组一手用户证据、各类来源的真实数据质量测试，以及专利/项目/获奖许可与标识的核查。

课程要求展示调研执行和支撑材料。本组目前能够提交真实的桌面调研台账、公开来源清单与访谈提纲，但不能提交不存在的访谈/问卷记录；如后续实施，须补充匿名汇总、日期、样本招募与同意说明，并重审需求优先级。SPEC 初稿将上述数据质量和检索原则转成可测试规则，具体阈值由小组复核后冻结。
